# Registro de ciclos TDD

Estado: sin ciclos ejecutados; no hay código de aplicación todavía.

Para cada regla de negocio, registrar:

1. ID del requisito y caso probado.
2. Prueba escrita antes de implementar.
3. Comando, fecha y salida roja: el fallo debe corresponder a la regla, no al entorno roto.
4. Cambio mínimo y salida verde.
5. Refactorización y nueva ejecución.
6. Referencias a archivos, commits y evidencias en `../evidencias/tdd/`.

Las pruebas de integración también deben demostrar que las transacciones impiden reservas simultáneas incompatibles. El informe final distinguirá pruebas unitarias, integración y demostración manual; incluirá cobertura y limitaciones reales.
